# Packaging Resonance as an MSIX and publishing it to the Microsoft Store

Everything needed lives in `packaging/`:

- `Package.appxmanifest` — the package manifest (identity values still to fill in, see step 2).
- `package.ps1` — builds the release exe, stages the layout, and packs `Resonance.msix`.
- `assets/` — the tile / store logos (teal equalizer mark, all required sizes), generated by `make-assets.ps1` — `package.ps1` runs it automatically when the PNGs are missing.

The short version: **(1)** reserve the app in Partner Center, **(2)** copy its
identity values into the manifest, **(3)** run `package.ps1`, **(4)** upload the
`.msix` in a Partner Center submission and fill in the listing. The Store signs
the package itself — you do **not** need a code-signing certificate for the
submission, only for installing the package on your own machine to test it.

## 1. Partner Center: account + name reservation

1. Register at [Partner Center](https://partner.microsoft.com/dashboard) as a
   Windows developer (individual account: one-time ~$19 fee).
2. **Apps and games → New product → MSIX or PWA app**, and reserve the name
   **Resonance** (if it's taken, pick a variant — the store display name can
   still read "Resonance" in the listing even if the reserved name differs
   slightly).
3. Open the product and go to **Product management → Product identity**. Note
   these three values — they go into the manifest verbatim:
   - Package/Identity Name (e.g. `12345YourName.Resonance`)
   - Package/Identity Publisher (e.g. `CN=XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX`)
   - Publisher display name (your developer name)

## 2. Fill in the manifest

In `packaging/Package.appxmanifest`, replace:

| Placeholder | Replace with |
| --- | --- |
| `REPLACE-WITH-IDENTITY-NAME` | Package/Identity Name |
| `CN=REPLACE-WITH-PUBLISHER-ID` | Package/Identity Publisher (keep the `CN=` form it shows) |
| `REPLACE-WITH-PUBLISHER-DISPLAY-NAME` | Publisher display name |

An exact match matters: if the manifest identity differs from Partner Center
by one character, the upload is rejected.

## 3. Build the package

From the repo root, in PowerShell:

```powershell
.\crates\resonance\packaging\package.ps1            # version 1.0.0.0
.\crates\resonance\packaging\package.ps1 -Version 1.1.0.0
```

The script runs `cargo build --release -p resonance`, stages
`packaging/build/layout` (exe + manifest + assets), and packs
`packaging/build/Resonance.msix` using `makeappx.exe` from the Windows SDK
(install it via Visual Studio's Windows SDK workload if missing). Bump the
version for every new submission — the Store requires each upload's version
to be higher than the previous one.

Notes on what's inside:

- The manifest declares a dependency on the **Windows App Runtime 2.x**
  framework package (`Microsoft.WindowsAppRuntime.2`) — that's what
  windows-reactor / WinUI 3 runs on, and declaring it makes Windows install
  it automatically on machines that don't have it.
- `runFullTrust` + `EntryPoint="Windows.FullTrustApplication"` is the
  standard shape for a packaged Win32 exe; `internetClient` covers
  streaming, downloads and the caches.
- A bonus of having a package identity: the media-session (SMTC) app name
  resolves properly as "Resonance" — the unpackaged Start-menu-shortcut
  workaround is no longer needed once the app is installed from the package.

## 4. Testing the package locally (optional, needs signing)

An unsigned `.msix` won't install. For a local test only:

```powershell
# One-time: a self-signed cert whose subject matches the manifest Publisher.
$cert = New-SelfSignedCertificate -Type Custom -Subject "CN=REPLACE-WITH-PUBLISHER-ID" `
  -KeyUsage DigitalSignature -FriendlyName "Resonance test" `
  -CertStoreLocation "Cert:\CurrentUser\My" `
  -TextExtension @("2.5.29.37={text}1.3.6.1.5.5.7.3.3", "2.5.29.19={text}")

# Sign the package (signtool is in the same Windows SDK bin folder as makeappx).
signtool sign /fd SHA256 /sha1 $cert.Thumbprint packaging\build\Resonance.msix

# Trust the cert (Local Machine > Trusted People), then install:
Add-AppxPackage packaging\build\Resonance.msix
```

**First-run note:** a packaged app's `%LOCALAPPDATA%` is virtualized into the
package's own storage, so the packaged build starts with fresh settings and
an empty catalog (the unpackaged build's data stays where it was). Downloads
in `Music\Resonance` are in a real folder and are unaffected.

## 5. The Store submission

In Partner Center, open Resonance and **Start your submission**, then work
through the checklist:

1. **Packages** — upload `Resonance.msix`. It validates the identity against
   step 1 automatically.
2. **Properties** — category: **Music** (or Entertainment); support contact
   email; system requirements are read from the package.
3. **Pricing and availability** — Free, all markets (or your choice).
4. **Age ratings** — complete the questionnaire (a music streaming app with
   user-generated/online content typically lands at 12+ / Teen depending on
   answers — answer honestly about online content).
5. **Store listings** (per language) — description, and **at least one
   screenshot** (capture the app at 1366×768 or larger; 1080p is fine). The
   tile logos come from the package; you can also upload a larger store icon
   here.
6. **Submission options** — rollout timing, notes for certification (e.g.
   "Streams music from JioSaavn; no account or login required to use the
   app" — testers need to know there's no sign-in wall).
7. **Submit for certification.** Review usually takes a few days; failures
   come back with a report (most common for Win32 MSIX: manifest identity
   mismatch — step 2 — or a crash on a clean machine, which the Windows App
   Runtime dependency in the manifest is there to prevent).

Once certified, the listing goes live on the chosen release schedule, and
future updates are just a new submission with a higher version number.
